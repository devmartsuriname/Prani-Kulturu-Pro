## 1. Samenvatting

Het Artmart-commerce-dashboard en de Artmart-verlanglijst zijn vóór live
onbereikbaar gemaakt, en de "Mijn account"-knop leidt nu naar een nieuwe,
niet-functionele inlogpagina. Er zijn twee losse routes bijgebouwd — `/login`
(Inloggen) en `/register` (Aanmelden) — **uitsluitend uit bestaande
ArtMart-blokken, -patronen en -assets** (PK-gebrande header/footer,
`breadcrumb-section2`, `enquery-section`/`form-inner3`-formulierpatroon). De zes
`/account*`-routes redirecten bij hard-load naar `/login` met behoud van de
dashboard-markup voor Fase 5; `/wishlist` blijft als referentie maar zonder de
commerce-biedtabel, met een lege PK-gebrande staat. Op de account-, wishlist-,
login- en registerpagina's is het tweede (Artmart-)header/footer-model vervangen
door de PK-shell (PK-logo, geen taalswitcher, NL zoekplaceholder, PK-footer).

**Resultaat:** acceptatietest 1–8 volledig groen. Taal- en commerce-sweep over 25
routes (incl. `/login`, `/register`, `/wishlist`): **0 bevindingen**. Header-check
over 25 routes × desktop+mobiel: account-knop én verlanglijst-icoon overal naar
`/login`, 0 taalswitchers, 0 Artmart-logo's, 0 fouten. `main.js` byte-identiek,
alle beschermde paden onaangeraakt. devmart-reviewer-verdict: **ACCEPT**.

Vijf lokale commits per werkpakket, **geen push** (gate-regel 2 blijft van kracht
tot Delroy's GO in CUT-5).

## 3. WP1 — /login en /register (ArtMart-only)

Beide pagina's zijn samengesteld uit blokken die al in de codebase in gebruik
zijn; er is geen nieuwe component of CSS toegevoegd (D-19).

| Onderdeel | Herbruikt patroon | Herkomst in repo |
| --- | --- | --- |
| Header | PK-shell (topbar + `header-area style-1`), PK-logo, NL zoekplaceholder, geen taalswitcher | donor `search.tsx` (identiek header-blok) |
| Banner | `breadcrumb-section2` met `top-content style-2` + `breadcrumb-content` | `events.index.tsx` |
| Formulier | `enquery-section style-3` → `enquery-form-wrapper` → `form-inner3` (label + input) | `about.tsx` / `contact.tsx` |
| Knop | `primary-btn1 btn-hover` met lege `<strong></strong>` (ripple-fill) | template-breed |
| Kruislink | `contact-area` met NL-tekst + anchor | `about.tsx` |
| Footer | PK-footer | donor `search.tsx` |

**Velden.** `/login`: e-mailadres + wachtwoord + knop **Inloggen**. `/register`:
naam + e-mailadres + wachtwoord + bevestig wachtwoord + knop **Aanmelden**.
**Kruislinks:** `/login` → "Nog geen account? Aanmelden" (`/register`); `/register`
→ "Al een account? Inloggen" (`/login`). Beide getest en werkend.

**DRAFT-markering.** Banner-intro en formulier-subkop vermelden expliciet dat het
een voorbeeldweergave (DRAFT) is en dat de functie in een volgende fase wordt
geactiveerd. De knoppen zijn `type="button"`; er is geen submit, action, fetch,
wachtwoordafhandeling of opslag — puur statische UI.

## 4. WP2 — account-knop naar /login

De account-anchor in de gedeelde header is uitsluitend herkend aan
`class="header-btn"` (desktop-topbar + mobiele `btn-area`) en van `/account` naar
`/login` gezet. Dit raakt **31 routebestanden, 62 anchors** (2 per bestand:
desktop + mobiel). Het label "Mijn account" blijft ongewijzigd (wordt in Fase 5
multi-functie). De dashboard-sidebarlink binnen `account.*` en het beschermde
`certificate.tsx` zijn bewust niet aangeraakt.

## 5. WP3 — account-dashboard onbereikbaar

Aan elk van de zes account-routes is toegevoegd:

```ts
import { createFileRoute, redirect } from "@tanstack/react-router";
// ...
  beforeLoad: () => {
    throw redirect({ to: "/login" });
  },
```

De `BODY_HTML` (dashboard-markup) en de `Page`-component zijn ongewijzigd, zodat
Fase 5 het dashboard weer kan activeren. Hard-load van elke route eindigt op
`/login` met de h1 "Inloggen"; het dashboard wordt niet zichtbaar
(`dashboardZichtbaar: false` op alle zes).

Artwork ID / Bid Amount / Place A Bid / Nft_-ID's / `$`-bedragen / "Ingangsdatum")

Het verlanglijst-icoon (`a.wishlist-btn`) in de gedeelde header is op **alle 31
routes** van `/wishlist` naar `/login` gezet. Sweep bevestigt: geen enkele
commerce-term of prijsnotatie meer aanwezig.

## 7. WP5 — header/footer-model PK-branden
